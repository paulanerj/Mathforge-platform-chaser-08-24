## QUESTION 1: What was the exact physical and logical sequence that caused the live deadlock in Greenfield V2?

**Answer:**  
In Greenfield V2, when the bot was at `(200, 201.4)` and the player was at `(350, 250)`, the below-player attack anchor was computed at `(350, 460)`. Goal candidates generated by proximity snapped the start cell `(200, 208)` into the goal list.

When `planPathV2()` ran A* search:
1. It inspected the start node `(200, 208)`.
2. Because `(200, 208)` was present in the candidate goal array, A* immediately terminated on step 1, returning `type: FULL`, `path: [(200, 208)]` (a 1-node path).
3. The movement controller measured distance to the single waypoint `(200, 208)` from current continuous position `(200, 201.4)` as `6.6px`.
4. Since `6.6px <= waypointArrivalPx (12px)`, the controller marked the waypoint reached.
5. Calculated movement displacement for the frame became `(0, 0)`.
6. The bot remained 299px away from the attack anchor `(350, 460)`, failing the `APPROACH -> STAGE` transition guard (`dist <= 24px`).
7. The progress monitor detected stall / zero movement and triggered `RECOVER`.
8. `RECOVER` immediately replanned using the same goal generator, which returned the exact same 1-node path `[(200, 208)]`.
9. The cycle repeated infinitely every frame, locking the bot in `CHASE <-> RECOVER` with zero movement.

## QUESTION 2: How does the Simplified Hybrid V2 architecture guarantee that a 1-node path will never cause a zero-movement deadlock again?

**Answer:**  
Simplified Hybrid V2 enforces a three-tier defense:

1. **Semantic Goal Purpose Specification:** Goals are tagged with semantic purpose (`ATTACK_READY` or `APPROACH_PROGRESS`). Candidates at or near the bot's current cell are generated ONLY if the bot satisfies `isBotInsideAttackEnvelope()` in world space.
2. **Planner Goal Predicate Validation:** `planPathV2Simplified()` validates whether a matching start cell actually satisfies the semantic goal condition. If a start cell matches a candidate goal but the bot is NOT inside the attack envelope, the start cell is explicitly rejected as a goal match, forcing A* to expand neighbors towards distant goals.
3. **Immediate Progress Faulting (`SEMANTIC_ZERO_MOVEMENT`):** `checkProgressV2()` calculates `Math.hypot(dx, dy)`. If the movement intent is zero while the bot is in `PURSUE` (outside the attack envelope), `checkProgressV2()` returns `false` immediately, faulting into recovery rather than idling.

## QUESTION 3: What happens when the bot enters the Attack Envelope? Why is local steering used instead of A* pathfinding?

**Answer:**  
When the bot crosses into the Attack Envelope (`abs(dx) <= 60px`, `dy >= 120px && dy <= 200px`), pathfinding overhead is unnecessary and counterproductive because:
1. The line-of-sight between the below-player staging area and the player is guaranteed clear by spatial inflation.
2. Grid-snapped A* paths produce discrete 16px stair-step jitter when operating at close quarters.

In Simplified Hybrid V2:
- Crossing into the Attack Envelope immediately transitions the state machine from `PURSUE` to `FINAL_APPROACH`.
- `FINAL_APPROACH` bypasses the A* planner entirely and uses a continuous proportional steering controller targeting `(player.x, player.y + 160)`.
- Vertical tracking is prioritized (`steerY *= 2.0`), providing smooth, continuous, non-jittery approach alignment prior to striking.

## QUESTION 4: How does Transit Corridor Protection prevent the bot from intercepting or camping the player's movement line?

**Answer:**  
When the player initiates a hop or circuit climb (`playerMovementState === 'MOVE_STARTED'` or `'IN_TRANSIT'`), a rectangular safety corridor is constructed around the player's starting and destination platforms (+/- 12px horizontal, +/- 60px vertical).

Transit Corridor Protection operates in two ways:
1. **Soft Transit Corridor Penalty (`corridorSoftCost = 36.0`):** During A* path expansion in `PURSUE`, grid cells intersecting the active transit corridor incur a heavy pathfinding cost penalty. The planner naturally routes the bot around the transit path unless no alternative exists.
2. **Directional Corridor Repulsion (`corridorRepulsionGain = 1.2`):** If the bot happens to be inside the corridor during `FINAL_APPROACH`, a lateral repulsion force (`steerX += repelDir * 36.0`) pushes the bot sideways out of the player's transit line.

## QUESTION 5: How are RECOVER state transitions protected against infinite same-frame re-entry?

**Answer:**  
In Greenfield V2, `RECOVER` could exit back to `CHASE` in the same tick if a path was found, allowing instant same-frame re-triggering.

Simplified Hybrid V2 enforces two strict state invariants:
1. **Non-Zero Duration Rule:** The frame that enters `RECOVER` is strictly forbidden from exiting `RECOVER` (`if (simTimeMs === recoveryStartTimeMs) return;`).
2. **Material Condition Requirement:** `RECOVER` can only exit to `PURSUE` if at least one material state condition has changed:
   - Bot moved >= 16px during recovery rung execution.
   - Player movement state changed (`MOVE_STARTED` or `IN_TRANSIT`).
   - Platform layout changed (`obstacleRevision` incremented).
   - Recovery rung escalated to rung 2+.

## QUESTION 6: Can the user switch back to the legacy or frozen V2 AI at runtime?

**Answer:**  
Yes. In the UI Live View Tuner panel (accessible via the gear icon in the top HUD), the `BOT AI` selector provides three options:
1. `V2_SIMPLIFIED` (Simplified Hybrid V2 - Default, active production engine)
2. `V2_FROZEN` (Greenfield V2 Frozen - Original unmodified 11A baseline)
3. `LEGACY` (V1 Legacy - Original simple patrol bot)

Switching the selector instantly resets and rebinds the active AI controller without requiring a app restart.
